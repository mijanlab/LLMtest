Docs/Security
Trust model

Local by default.

LLMtest is designed to benchmark your chosen endpoint without turning credentials or results into a hosted service.

Credential handling

API keys are accepted through the interactive prompt or command-line arguments and held in process memory for the duration of the run. LLMtest uses the value only to set the authorization header for requests sent to the endpoint you provide.

Keys are not persisted by LLMtest

Credential values are not added to generated HTML, Markdown, CSV, or JSON reports and are not written to the benchmark configuration file.

Network requests

The benchmark contacts only the endpoint supplied by the user: first to retrieve the model list and then to stream chat completions. Update operations contact the project repository through the active Python package manager.

  • Review the endpoint hostname before entering a key.
  • Use provider-scoped credentials with the minimum required privileges.
  • Rotate a credential immediately if it appears in shell history or logs.
  • Avoid benchmarking sensitive prompts against third-party providers.

Report privacy

Reports may contain model identifiers, endpoint URLs, prompts, response previews, errors, performance measurements, and timestamps. They do not contain the API key. Treat output files according to the sensitivity of the prompts and responses used in your run.

Review before sharing

Response previews and raw result details can contain content returned by a model. Inspect generated files before attaching them to public issues or repositories.

Offline HTML

The generated benchmark dashboard packages its styles, scripts, and data into one HTML file. It requires no backend server and loads no analytics or CDN resources when opened.

Dependencies and updates

The benchmark implementation relies on Python libraries available in the repository environment. The installed CLI declares Requests as its only runtime dependency. Review upstream package and repository changes before updating in controlled environments.

Report a security concern

Avoid opening a public issue containing a credential or exploit detail. Contact the project maintainer through the channels listed on the GitHub repository.
